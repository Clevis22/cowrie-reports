About

I run an SSH honeypot to study login attempts, shell commands and file transfers. This site collects the daily reports.

How the shell works

The honeypot runs a custom fork of Cowrie. It combines Cowrie’s regular emulated shell with an LLM fallback powered by Tencent’s HY4 Flash. There is no guest VM behind the shell.

Cowrie handles known commands first. Its command handlers and virtual filesystem manage paths, file contents, working directories, shell variables, pipes and redirects. A shared machine profile keeps the emulated system’s details consistent across commands.

If a command has no native handler and qualifies for fallback, HY4 Flash receives a bounded description of the current session and generates terminal output and an exit status. Requests go through OpenRouter. A few catalogued virtual utilities also use this path. Existing command errors and invalid options keep their normal Cowrie behavior.

The model has no tools to run host commands, install software or execute uploads. Cowrie still owns the virtual filesystem and shell state. Redirecting generated output can create a virtual file through Cowrie’s normal shell handling. If the model is unavailable or a request hits its limits, the command returns a local error.

Ollama API decoy

A separate Rust service imitates an Ollama API. It records discovery requests, submitted prompts and model-management attempts, and returns short canned replies. It keeps no conversation state.

Daily reports summarize request counts, endpoints, requested models and capture gaps. Raw prompts and request bodies stay in the private logs. An API success response comes from the simulation.

What the reports show

Reports cover recorded commands, session activity and file observations. Captured transfer bytes, emulated behavior and model-generated text are kept distinct. A command that attempts to launch a file does not prove it ran; a generated system description does not establish real hardware.

This is partial shell emulation. Unsupported commands, inconsistent responses and model latency can still give it away. The goal is to collect useful observations, and the reports should make those limits clear.

Hermes Agent writes the reports in Markdown. GitHub Actions builds the pages and archive, and GitHub Pages hosts them. The public site contains report text, separate from the private investigation dashboard.

Projects and resources

  • Ollama API — the interface imitated by the API decoy. The service uses Rust, Tokio and Hyper.
  • Cowrie — the honeypot, SSH handling and emulated shell. Documentation.
  • Tencent HY4 Flash — the fallback language model. Model on OpenRouter.
  • Everforest by sainnhe — the site’s Dark Hard color palette. Palette reference.
  • Hermes Agent by Nous Research — report writing.
  • Python, Twisted / Conch and Lark — the runtime, networking and SSH framework, and parser used by Cowrie.
  • markdown-it-py, mdurl and PyYAML — Markdown rendering, URL handling and report metadata.
  • MalwareBazaar, URLhaus and VirusTotal — reputation references used during investigation. A reputation result is separate from the sensor’s own evidence.
  • Site source and publishing instructions — templates, Markdown format and build workflow.
Other Cowrie Python dependencies

attrs, bcrypt, cryptography, hyperlink, idna, packaging, pyasn1-modules, service-identity and treq. These accompany Twisted and Lark in Cowrie’s direct runtime dependencies.
