## Summary

The sensor logged 2,240 external sessions from 158 addresses between 01:06:01Z on 23 November and 01:06:01Z on 24 November. 1,675 sessions ran no commands. Of the 565 that did, 551 ran the same GPU and host inventory, and 6,500 commands were recorded in total.

Two addresses in AS198364, 109.160.32.147 and 109.160.32.115, sent 1,108 sessions, 49.5% of the day. All 1,108 session starts fall between 19:28:16Z and 22:19:56Z, a span of 2 h 51 m 40 s. The sensor logged 1,470 external sessions from 27 addresses inside that span, so the pair is 75.4% of the traffic in it, not all of it. The clock hours 19:00Z through 22:00Z produced 1,363 sensor-wide sessions; the pair accounted for 1,000 of those.

## What the bots did

`connect-only` explains 1,675 sessions, `gpu-recon` 551, `host-recon` 9, `other-command` 3 and `payload-fetch` 2. Every non-zero command bucket is accounted for below.

**`gpu-recon`, 551 sessions.** 529 ran this six-command block and nothing else:

- `uname -s -v -n -r -m`
- `nproc`
- `lspci | egrep VGA && lspci | grep 3D`
- `lscpu | egrep "Model name:" | cut -d ' ' -f 14-`
- `nvidia-smi -q | grep "Product Name"`
- `curl ipinfo.io/org`

The other 22 prefixed a cleanup block. Twenty-one ran the same 771-character command: `crontab -r ; rm -rf /var/tmp/.* /var/tmp/* /tmp/.* /tmp/* ; … for proc in xmrig cpuminer minerd ccminer; do … pkill -9 $proc … done`. It clears cron, deletes temporary files and kills four named miner processes. That reads as evicting competing mining software; it is an inference from the command, not proof it worked on a real host. One variant, session `cf703fe2a2ae` from 106.13.170.216, also removed `.diicot`, `.black` and `.update-logs`, killed `java` and `cnrig`, then ran `chmod 777 bKFKuvfT ; ./bKFKuvfT </dev/null &>/dev/null & disown` and `history -c`. The emulated shell answered `Command not found: ./bKFKuvfT`, so the binary was not present and execution is not evidenced. The command implies a staged file at `/var/tmp/bKFKuvfT`; no upload of that name appears in this window.

Collecting GPU product names, VGA and 3D devices, CPU model, core count, uptime and the host's own organisation is consistent with selecting machines for mining. This is inferred from the command set; all output is emulated, so none of it is hardware evidence.

**`host-recon`, 9 sessions.** Seven from 106.13.170.216 ran one or two commands, `uname -s -v -n -r -m` and, in three cases, `nproc`. One from 109.160.32.115 ran `uname -s -v -n -r -m`, `uname -m | awk '{printf $1}'`, `uptime | grep -ohe 'up .*' …` and `nproc`. The ninth, from 58.242.117.126, was a nine-command sweep with `/ip cloud print`, `ifconfig`, `uname -a`, `/proc/cpuinfo`, two `ps` greps for miner processes, and a list of paths covering Telegram Desktop `tdata` directories, GSM modem devices, `smsd` logs and `simman` configs, plus `locate D877F783D5D3EF8Cs`. That path list is consistent with looking for messaging sessions and SMS modem data, not with GPU selection.

**`other-command`, 3 sessions.** Each ran one command, `echo xsec`, from 202.165.25.8, 164.30.7.153 and 27.102.116.43. It looks like a marker or handshake check; nothing followed it.

**`payload-fetch`, 2 sessions.** Both belong to 109.160.32.147 and both moved bytes toward the sensor. `scp -qt` is the receive side of an SCP push, so this bucket is ingress, not a fetch:

- session `909d834b9ec1`, 19:29:50Z: `scp -qt "/var/tmp/cviUrCFS"`, 2,588,672 bytes captured, `capture_complete: false`, stream sha256 `8ef6910298e9e0851546bc849c70cc549370e8c41dd9d57bffd33159c5ae299c`
- session `b9333f26e9df`, 19:46:57Z: `scp -qt "/var/tmp/OLeJDGSw"`, 2,555,928 bytes captured, `capture_complete: false`, stream sha256 `a42f9e235f2ff0cdd7cd7708f8e6b9ecbb7e4b7c2970bc0c3088c020025b1643`

No URL appears in either command. No `http://`, `https://` or `ftp://` URL appears in any external command in the window; the only outbound reference is `curl ipinfo.io/org`, an ASN lookup. Outbound traffic from the sensor is blocked, so a fetch would fail regardless. The two sha256 values above are hashes of incomplete channel captures, not of completed files, and neither appears in `artifact_intel`.

## Method and limits

Window: 2026-11-23T01:06:01Z to 2026-11-24T01:06:01Z, 24 hours, taken from the Cowrie hybrid sensor's compressed segments in the collector's Drive folder. Loopback and harness-marked sessions are excluded from external counts; 252 such sessions and 10 addresses were set aside. A successful login is against the honeypot's own credential list, not a real host. A captured hash proves capture, not execution. Stream hashes marked incomplete cover only the bytes received. Emulated shell output and LLM replies are not evidence of hardware or network state.
